# Спецификация формата файла подсказок (.hints)

## 1. Назначение

Файл `.hints` предоставляет пользователю механизм для ручного управления генерацией FFI-метаданных (`immeta` и `cbmeta`) в C#-трансляторе. Правила, определенные в этом файле, имеют наивысший приоритет и переопределяют любой автоматический эвристический анализ, выполняемый транслятором.

Это позволяет точно настраивать маршалинг данных для сложных или нестандартных нативных функций, а также исправлять ошибки автоматического анализа.

## 2. Использование

### 2.1. Автоматический поиск

По умолчанию, для входного файла `my_project.bc`, транслятор будет автоматически искать файл подсказок с именем `my_project.hints` в той же директории. Если файл не найден, будет создан шаблон с примерами.

### 2.2. Явное указание файла

С помощью флага командной строки `-hi` можно явно указать путь к файлу подсказок. Это полезно, если вы хотите использовать один файл подсказок для нескольких `.bc` файлов или если файл находится в другом месте.

**Пример:**
```bash
dotnet llvm_espb\bin\Debug\net9.0\LLVM_ESPB.dll -hi llvm_espb\test_hints.hints -h llvm_espb\hello_world_main.bc main\test.espb
```

## 3. Синтаксис

- **Кодировка**: UTF-8.
- **Комментарии**: Строки, начинающиеся с `#`, игнорируются.
- **Пустые строки**: Игнорируются.
- **Формат строки**: `имя_функции: правило1, правило2, ...`
- **Разделители**:
  - `:` отделяет имя функции от списка правил.
  - `,` разделяет правила друг от друга.
  - Пробелы используются для разделения частей внутри одного правила.

## 4. Правила (Ключевые слова)

##4.1. Управление immeta (входные/выходные параметры)

+--------------------+-------------------+----------------------------------------------------+
| Ключ/Модификатор   | Пример            | Описание                                           |
+--------------------+-------------------+----------------------------------------------------+
| in <idx>           | in 0              | Параметр <idx> входной (IN). Копируется в буфер.   |
+--------------------+-------------------+----------------------------------------------------+
| out <idx>          | out 1             | Параметр <idx> выходной (OUT). Копируется из буф.  |
+--------------------+-------------------+----------------------------------------------------+
| inout <idx>        | inout 2           | Параметр <idx> вход/выход (INOUT). Данные в обе    |
|                    |                   | стороны.                                           |
+--------------------+-------------------+----------------------------------------------------+
| async              | out 1 async       | Для out/inout. Запись в буфер асинхронна.          |
+--------------------+-------------------+----------------------------------------------------+
| size[<const>]      | in 2 size[256]    | Размер буфера задан явно в байтах.                 |
+--------------------+-------------------+----------------------------------------------------+
| size from <idx>    | out 1 size from 5 | Размер буфера берётся из параметра 5.              |
+--------------------+-------------------+----------------------------------------------------+
| size strlen <idx>  | out 0 size strlen 1| Размер = strlen(param[idx]) + 1. Для strcpy и др.  |
+--------------------+-------------------+----------------------------------------------------+
| no im <idx>        | no im 2           | Запрещает immeta для параметра <idx>.              |
+--------------------+-------------------+----------------------------------------------------+
| no im              | no im             | Запрещает immeta для всей функции.                 |
+--------------------+-------------------+----------------------------------------------------+


##4.2. Управление cbmeta (обратные вызовы)

+------------------------+-----------------+----------------------------------------------------+
| Ключ/Модификатор       | Пример          | Описание                                           |
+------------------------+-----------------+----------------------------------------------------+
| cb <idx>               | cb 3            | Параметр <idx> — функция обратного вызова.         |
+------------------------+-----------------+----------------------------------------------------+
| ud <idx> for <cb_idx>  | ud 4 for 3      | Параметр <idx> — user_data для колбэка <cb_idx>.   |
+------------------------+-----------------+----------------------------------------------------+
| no cb <idx>            | no cb 3         | Параметр <idx> не является колбэком.               |
+------------------------+-----------------+----------------------------------------------------+
| no cb                  | no cb           | Запрещает cbmeta для всей функции.                 |
+------------------------+-----------------+----------------------------------------------------+
| no ud <idx> for <cb>   | no ud 4 for 3   | Отключает user_data <idx> для колбэка <cb>.        |
+------------------------+-----------------+----------------------------------------------------+
## 5. Примеры

```
# Пример для функции создания задачи в FreeRTOS
xTaskCreatePinnedToCore: cb 0, ud 3 for 0, out 5 async

# Пример функции, читающей данные в буфер
# Параметр 0 - это буфер для записи (out), его размер передается в параметре 1.
my_read_func: out 0 size from 1

# Пример для strcpy - размер буфера = strlen(src) + 1
# Параметр 0 - dest (out), размер определяется по strlen параметра 1 (src)
strcpy: out 0 size strlen 1

# Пример для функции с комплексным INOUT параметром
# Параметр 2 - это указатель на структуру, которую нужно сначала передать в функцию, 
# а потом прочитать измененное значение. Размер структуры - 12 байт.
update_struct: inout 2 size[12]

# Пример для отключения анализа для "проблемной" функции
# Транслятор будет считать, что у функции my_buggy_func нет ни колбэков, ни указателей для маршалинга.
my_buggy_func: no im, no cb

# Пример для управления user data в callback'ах
# Создаем callback на параметре 3, но отключаем user data на параметре 4 для этого callback'а
xTimerCreate: cb 3, no ud 4 for 3

# Комплексный пример: переопределение callback с отключением старого user data
# Отключаем callback на параметре 4, создаем новый на параметре 3 с user data на параметре 4,
# но затем отключаем этот user data
complex_callback_func: no cb 4, cb 3, ud 4 for 3, no ud 4 for 3
